# Synthea sample dataset

The quick-start dataset. Everything in `sample/` is **synthetic**: generated by
[Synthea](https://github.com/synthetichealth/synthea) (Apache-2.0), with no real
patient data. The names, SSNs and addresses are made up.

## What's here

`sample/` holds the five core tables ForgeMesh's Synthea project uses, gzipped (~5 MB):

| File | Bronze table | Rows |
|---|---|---|
| `patients.csv.gz` | `raw_patients` | 585 |
| `encounters.csv.gz` | `raw_encounters` | 37,633 |
| `conditions.csv.gz` | `raw_conditions` | 22,019 |
| `medications.csv.gz` | `raw_medications` | 32,873 |
| `procedures.csv.gz` | `raw_procedures` | 102,064 |

Generation parameters: Synthea `0a934f8`, Massachusetts, `-p 500`, 10 years of
history, reference date 2026-02-28, seed `1772272958275`.

## Loading it

```bash
python scripts/load_synthea.py
```

This creates `bronze_synthea`, `silver_synthea` and `gold_synthea` in the local
MySQL (`localhost:3307`) and loads the five bronze tables. Set `DATABASE_URL` to
use a different server.

## Using your own Synthea output

Generate CSVs with Synthea (`./run_synthea -p 500 --exporter.csv.export=true`),
then either copy `output/csv/` to `datasets/synthea-output/csv/` (gitignored, and
used automatically when present) or pass the directory explicitly:

```bash
python scripts/load_synthea.py --csv-dir /path/to/synthea/output/csv
```

A different population loads and runs fine. The Synthea E2E gate
(`tests/synthea/test_e2e_gate.py`) was developed against this sample, though.
